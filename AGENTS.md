# Quake3-iOS

<!-- AUTO-MANAGED: project-description -->
Native iOS port of Quake 3 Arena using Metal rendering. SwiftUI app shell wrapping an MTKView-based renderer that bridges to C/C++ engine code via a bridging header.
<!-- END AUTO-MANAGED -->

<!-- AUTO-MANAGED: architecture -->
## Architecture

```
Quake3-iOS/
├── Quake3_iOSApp.swift              # @main SwiftUI entry point
├── MetalView.swift                  # MTKView wrapper + inline MSL shaders
├── Quake3-iOS-Bridging-Header.h     # C/C++ bridge
├── Info.plist
code/                                # C/C++ Quake 3 engine source
baseq3/                              # Game assets
Resources/
```

**MetalView.swift** is the core renderer. It contains:
- `MetalView`: `UIViewRepresentable` wrapping `MTKView`
- `Coordinator`: `MTKViewDelegate` holding GPU structs and inline MSL shader source
- Fourteen render pipelines: UI (`q3_ui_*`), World opaque/filter/alpha/additive/additive-full (`worldPipelineState`, `worldFilterPipelineState`, `worldAlphaPipelineState`, `worldAdditivePipelineState`, `worldAdditiveFullPipelineState`), Sky opaque/additive (`skyPipelineState` — spherical projection, no depth write; `skyAdditivePipelineState` — src=ONE/dst=ONE for multi-stage sky overlays; `skyAdditiveFullPipelineState` — alias for skyAdditivePipelineState), Entity opaque/filter/alpha/additive/additive-full (`entityPipelineState`, `entityFilterPipelineState`, `entityAlphaPipelineState`, `entityAdditivePipelineState`, `entityAdditiveFullPipelineState`)
- World draw loop: **five passes** (0=opaque, 1=filter, 2=alpha, 3=additive src-alpha, 4=additive-full GL_ONE/GL_ONE)
- Entity draw loop: **six passes** (0=opaque, 1=filter, 2=alpha, 3=additive src-alpha, 4=subtract, 5=additive-full GL_ONE/GL_ONE)
- color-attachment `loadAction=.load` / `storeAction=.store`: required so destinationColor is preserved for GL_DST_COLOR/GL_ZERO (filter) and GL_ZERO/GL_ONE_MINUS_SRC_COLOR (subtract/decal) passes

### Native VM Linking (iOS)

All three game modules (cgame, qagame, ui) are statically linked into the iOS binary. They each define identical symbols (`vmMain`, `dllEntry`, file-static `syscall`); the following scheme avoids linker collisions:

**CGAME_NATIVE rename macros** (`cg_local.h`):
- When `-DCGAME_NATIVE` is set by the Xcode target, `#define` aliases: `vmMain → CG_vmMain`, `dllEntry → CG_dllEntry`, `syscall → CG_syscall`
- Inactive for QVM builds — standard QVM toolchain still sees canonical names
- Include order: `qcommon.h` included inside the `#ifdef CGAME_NATIVE` block, BEFORE `cg_public.h` — `cg_public.h` references `COM_TRAP_GETVALUE` defined in qcommon.h; QVM builds never saw qcommon.h
- `Q_PRINTF_FUNC(fmt, va)` and `Q_NO_RETURN` stubbed to no-ops inside `#ifdef CGAME_NATIVE` — ioq3 cgame uses these compiler-attribute macros; Quake3e's q_shared.h doesn't define them

**`code/cgame/cg_native.c`** (compiled only with `CGAME_NATIVE`):
- Declares `extern CG_vmMain` / `extern CG_dllEntry` (emitted by renamed cgame symbols)
- Exports `CG_Native_GetEntryPoint()` → `vmMainFunc_t` and `CG_Native_GetDllEntry()` → `dllEntry_t`
- Called from `ios_main.m`'s `Quake3_Init()` to pass pointers to `VM_RegisterNative("cgame", ...)`

**`code/cgame/cg_main.c`** compatibility guards:
- `Com_Error` and `Com_Printf` local stubs wrapped in `#ifndef CGAME_NATIVE` — in native builds these come from the engine via qcommon.h; QVM stubs are only compiled for QVM builds

**`code/cgame` source group** (`project.yml`):
- Compiled into main app binary with `-DCGAME_NATIVE=1 -Wno-strict-prototypes -Wno-pointer-sign`
- `cg_newdraw.c` excluded (MISSIONPACK only; has `#error This file not be used for classic Q3A` guard)
- Shared game/cgame code: `bg_misc.c`, `bg_pmove.c`, `bg_slidemove.c` compiled directly; `bg_lib.c` is `buildPhase: none` (string helpers only needed for QVM/nolibc)

**Static native-module registry** (`code/qcommon/vm.c`):
- `vmNativeModule_t` struct: `name[32]`, `vmMainFunc_t vmMain`, `dllEntry_t dllEntry`
- `s_nativeModules[4]` static table; `VM_MAX_NATIVE_MODULES = 4`
- `VM_RegisterNative(name, vmMain, dllEntry)` — inserts or replaces by name; warns and drops if table full
- `VM_Create()` native-module registry check is **unconditional** — `VM_FindNative(name)` is called before any interpret-mode branching, not gated on `interpret == VMI_NATIVE`. Required because `vm_cgame` defaults to `VMI_COMPILED` on most platforms; the old gate caused the iOS-embedded cgame to be silently skipped and the engine to fall through to QVM. After the registry check, the original VMI_NATIVE dylib/dlopen path and demo-restriction guard run as before.
- Public API declared in `code/qcommon/qcommon.h`: `vmMainFunc_t`, `dllEntry_t`, `VM_RegisterNative`

**Registration call site** (`ios_main.m`, `Quake3_Init()`):
- After `Com_Init()` and before `IN_Init()`: calls `VM_RegisterNative("cgame", CG_Native_GetEntryPoint(), CG_Native_GetDllEntry())`
- `CG_Native_GetEntryPoint` / `CG_Native_GetDllEntry` declared `extern` inline at the call site
- Effect: `VM_Create(VM_CGAME, ..., VMI_NATIVE)` on map load hits the registry; cgame.qvm is NOT loaded; cgame now reads/writes the same Quake3e structs the engine uses (eliminates QVM ABI mismatch)

## Conventions

- Inline MSL shaders compiled at runtime from `shaderSource` string in `Coordinator`
- GPU vertex structs mirror MSL counterparts: `GPUVertex`, `GPUWorldVertex`, `GPUEntityVertex`
- Uniform structs: `Uniforms`, `WorldUniforms`, `WorldDrawUniforms`, `EntityUniforms`
- MTKView configured: `bgra8Unorm` color, `depth32Float` depth, display-rate FPS, continuous rendering (`isPaused = false`)
- Controller button bitmask: `Q3_PAD_*` constants defined in `code/ios/ios_local.h` (bits 0–15). Swift mirrors them in `GameControllerBridge.PadBit`. C side maps bits to `K_PAD0_*` keycodes in `s_gamepadBitMap[]` (ios_main.m). `IN_Frame` diffs `prev ^ cur` buttonMask and queues `SE_KEY` events per toggled bit — do not add per-button polling on top of this.
- Controller bind installation: `IN_Init` uses `Cbuf_AddText` + `Cbuf_Execute` to install all `PAD0_*` binds and joystick cvars. Do NOT use `Cbuf_ExecuteText(EXEC_NOW, ...)` for multi-line bind scripts: `EXEC_NOW` calls `Cmd_ExecuteString` on the whole string and stops at the first newline — only the first command runs, all subsequent binds are silently dropped. `Cbuf_AddText` queues the full multi-line block; `Cbuf_Execute` drains every command to completion. After the block runs, verify with `Cbuf_ExecuteText(EXEC_NOW, "bind PAD0_A\n")` etc.

## Patterns

- **World debug modes**: `worldDebugMode` static `Float` on `Coordinator` (default `0`). Values: `0`=normal, `1`=base texture only, `2`=lightmap only, `3`=UV1 visualization, `4`=vertex color only. Change at compile time to diagnose rendering issues.
- **Alpha-test**: Per-shader-stage opt-in, NOT a global discard. `WorldDrawUniforms.alphaTestThreshold` (MSL: `float alphaTestThreshold`) encodes the test: `>0` → discard if `texel.a < threshold` (GT0=0.004, GE128=0.5); `<0` → discard if `texel.a >= |threshold|` (LT128=-0.5); `0` = no test. Per-draw threshold is now set from `stage.alphaFunc` via `Coordinator.alphaTestThreshold(for:)` in the Swift draw loop — each world stage's `alphaFunc` field drives the uniform directly. The NOCULL heuristic (`d7d2243`) was reverted before this per-draw wiring was added. Unconditional global discard (removed in `37bea83`) must NOT be restored: causes transparent geometry on surfaces whose stage0 texture falls back to white.
- **Entity pipeline diagnostics**: `RE_ClearScene` resets four per-frame counters (`s_entityAcceptedThisFrame`, `s_entityRejectedNullThisFrame`, `s_entityRejectedTypeThisFrame`, `s_entityRejectedModelThisFrame`) and increments `s_clearSceneCalls`. `RE_AddRefEntityToScene` increments `s_rawEntryCount` unconditionally (even for null/invalid). `RE_RenderScene` increments `s_renderSceneCalls` and logs the per-frame accept/reject counts every `s_sceneLogCounter` interval, plus the first accepted entity's origin/axis/renderfx/hModel/reType. Use `s_clearSceneCalls`/`s_renderSceneCalls`/`s_rawEntryCount` to detect if cgame is submitting at all vs. the pipeline rejecting.
- **Tag-only MD3s**: `LoadMD3ModelData` accepts `numSurfaces == 0` (changed from `< 1` to `< 0`). Models with only tags and no renderable surfaces are valid (e.g., attachment point markers).
- **Optional model path logging**: `TryRegisterModelPath` logs missing pk3 files at `PRINT_DEVELOPER` (not `PRINT_WARNING`). Missing optional paths are expected; only log at warning level for true failures.
- **Synthetic first-person viewmodel (REMOVED, b62874c)**: `SynthesizeViewmodelEntity`, `GetViewmodelHandle`, `EnsureViewmodelCvars`, `metal_vm_forward`/`right`/`up`/`scale`/`sway` cvars, `metal_synth_viewmodel` cvar, and `metalSceneEntity_t.isSynthetic` were all removed as dead code. These were QVM-ABI-mismatch workarounds: native cgame (commit 5977485) submits the real viewmodel at the correct `tag_weapon` position with proper animations, making the synthetic injection layer obsolete. The quad-shell duplicate-emit that shadowed `customShader` was also removed. `metal_fallback_camera` is intentionally kept as a cheap refdef-repair diagnostic (see its entry below).
- **visionOS platform support** (`c528f98` + `3398ac8`): `project.yml` and `Quake3-iOS.xcodeproj/project.pbxproj` expand `SUPPORTED_PLATFORMS` to include `xros xrsimulator`, add device family `7` to `TARGETED_DEVICE_FAMILY`, and set `XROS_DEPLOYMENT_TARGET = 26.4`. Per-SDK xcconfig conditionals limit `INFOPLIST_KEY_LSRequiresIPhoneOS` and `INFOPLIST_KEY_UIRequiresFullScreen` to iphoneos/iphonesimulator only (visionOS does not accept them); those keys are dropped from the static `Info.plist`. `MetalView.swift` guards the frame-rate query: `#if os(visionOS) let maxFPS = 90 #else UIScreen.main.maximumFramesPerSecond #endif` — visionOS does not expose `UIScreen.main`. iOS device + Simulator builds remain green. No visionOS-specific rendering code beyond the maxFPS guard; the wiring enables the target but a visionOS build has not yet been attempted.
- **Entity depth-hack**: `MetalView.swift` keeps two entity depth-stencil states: `depthStencilState` (`.lessEqual`, default) and `depthHackDepthStencilState` (`.always`, depth write on). Per-draw entity loop switches state based on `draw.flags & Q3_METAL_ENTITY_DRAWFLAG_DEPTHHACK`. Used so the first-person viewmodel never gets occluded by world geometry while still self-occluding correctly.
- **World-scene state preservation** (THREE-PART, permanent architectural pattern): cgame calls `RE_ClearScene` before every scene in a frame — world scene, then each HUD/2D scene. This means ClearScene fires N times per rendered frame, not once. All three parts below must stay coherent; reverting any one causes render breakage.
  1. **`RE_ClearScene` does NOT reset `s_entityVertexCount`/`s_entityIndexCount`/`s_entityDrawCount`**. It still resets `s_sceneEntityCount` and the per-scene accept/reject counters. Rationale: resetting draw buffer counts in ClearScene wiped the world scene's built geometry before the subsequent HUD scenes' `RE_RenderScene` ran, producing nothing to draw.
  2. **In `RE_RenderScene`, the `s_entity{Vertex,Index,Draw}Count = 0` resets and the `if (s_sceneEntityCount > 0) { ... build loop ... }` block are both gated on `fd->rdflags == 0`**. Only world scenes (rdflags 0) rebuild the entity buffers; HUD scenes retain the previous world buffer intact.
  3. **In `RE_RenderScene`, the `s_sceneView` write-out (fovX/fovY/viewOrigin/viewAxis) is also gated on `fd->rdflags == 0`**. Required because preserving world entity draws is useless if sceneView is still overwritten by a HUD camera — world-space coordinates would project off-screen. Regression history: parts 2+3 alone caused all-invisible because ClearScene's buffer-count resets still ran between scenes.
- **BSP lightgrid entity lighting**: `metalWorld_t` carries BSP lightgrid data: `const byte *lightGrid`, `vec3_t lightGridOrigin`, `vec3_t lightGridSize` (default 64×64×128 cell dims), `int lightGridBounds[3]` (cell counts per axis). Loaded from `LUMP_LIGHTGRID` in `LoadWorldMapData`; each cell is 8 bytes: `ambient[3] + directed[3] + latLong[2]`. `SetupEntityLighting(entity, outAmbient, outDirected, outLightDir)` samples the lightgrid at the entity's lighting origin: clamps to grid bounds, trilinearly samples ambient/directed RGB and decodes the lat/long light direction. In `RE_RenderScene`, per-vertex Lambert diffuse is applied to each MD3 vertex: decode MD3 lat/long normal (high byte=lat, low byte=lng, both `[0..255]`→`[0, 2π]`) as `N = (cos(lat)·sin(lng), sin(lat)·sin(lng), cos(lng))` (localN is unit length by construction), rotate to world space via `effectiveAxis`, **then `VectorNormalize(worldN)` as a defensive renormalize** — cgame's `entity.axis` can drift out of orthonormality over time, leaving the rotated `worldN` slightly >1 or <1 and producing clamped/bogus `N·L` values. `VectorNormalize` returns early on zero-length vectors so it's safe. Compute `ndotl = clamp(N·lightDir, 0, 1)`, final vertex color = `(ambient + directed * ndotl) * entityColor` clamped to `[0,1]`. Replaces the previous flat `entityColor` assignment. Effect: MD3 entities pick up per-room ambient/directional lighting instead of always rendering full-white.
- **Multi-stage world draw API**: `Q3MetalWorldDrawCmd` is stage-based — flat `textureHandle`/`texCoordScale`/`texCoordScroll` top-level fields replaced by `stageCount` + `stages[Q3_METAL_MAX_STAGES]` array of `Q3MetalWorldStage` structs. Each stage carries: `textureHandle`, `blendMode`, `tcGen`, `tcMod`, `tcModParams[4]`, `rgbGen`, `alphaFunc`. `SetupWorldDraw(draw, firstIndex, indexCount, lightmapTextureHandle, flags)` initializes draw with `stageCount=0`. `AddWorldDrawStage(draw, textureHandle, blendMode, tcGenEnv, tcModType, tcModP0..P3, rgbGen, alphaFunc)` appends one stage (guards `>= Q3_METAL_MAX_STAGES`). MetalView.swift iterates `draw.stages[n]` per stageIndex via `Coordinator.worldStage(_:_:)` helper; `Coordinator.stageTcModParams(_:)` converts the C tuple `tcModParams` to `SIMD4<Float>`. Each stage's `blendMode` determines the pass (0=opaque, 1=additive, 2=alpha, 3=filter). The old flat `draw.textureHandle` field is gone.
- **tim_hell sky artifact fix**: `IsTimHellShaderName` now unconditionally returns `qfalse` (parameter is `(void)`-discarded). The previous `textures/skies/tim_hell` check enabled local-geometry rendering of that sky shader directly on BSP polys, producing obvious rectangular geometry artifacts around q3dm1's teleporter area. Sky shaders now flow exclusively through the generic `IsSkyShaderName` → cubemap/cloud-dome decision tree.
- **Sky pipeline** (`skyPipelineState` + `skyAdditivePipelineState` + `skyDepthStencilState`): Dedicated MSL shaders `q3_sky_vertex` / `q3_sky_fragment` handle sky BSP surfaces. Vertex shader outputs world-space position and pushes `z = w` so sky is always at the far plane (renders behind everything without depth write). Fragment shader computes view direction `dir = normalize(worldPos - cameraPos)` then maps UV via **axis-blended cube projection** (NOT lat-lon, NOT hard dominant-axis): three cube projections (`uvX`, `uvY`, `uvZ`) are computed and blended with weights `w = pow(|dir|, 4) / sum(pow(|dir|, 4))` — `pow(4)` sharpens each axis contribution near its face and softens it into adjacent faces, eliminating hard seams at face boundaries. `1e-4` floor prevents divide-by-zero on exact axis directions. This avoids the zenith singularity lat-lon produces and the diagonal banding seen with hard cube-face switching. tcMod scroll/scale applied identically to all three projections so motion stays coherent. Fragment applies `tcMod=1` scroll (`uv += tcModParams.xy * timeSeconds`) or `tcMod=4` scale (`uv *= tcModParams.xy`) per stage. Swift sky branch iterates **all stages** in `draw.stages[]`: stage 0 renders through `skyPipelineState`; subsequent stages with `blendMode == 1` render through `skyAdditivePipelineState` (src=ONE, dst=ONE) — this composites killsky_2 cloud overlay on top of killsky_1 base. `skyDepthStencilState` uses `.lessEqual` with depth write OFF for all sky stages. Sky draws are emitted only during world pass 0 (opaque) to avoid duplicate draws across the four-pass loop. `WorldUniforms` carries `cameraPos: SIMD3<Float>` (padded to 16-byte with `_pad: Float`) needed by the sky fragment for view-direction computation. **CRITICAL**: `WorldUniforms` must be bound to BOTH vertex index 1 AND fragment index 1 via `encoder.setFragmentBytes(&worldUniforms, length:, index: 1)` in the shared world setup block. The world fragment shader does not read `WorldUniforms`, but the sky fragment does — without the fragment bind, `uniforms.cameraPos` reads undefined memory and produces vertical smear bands across the sky and commonly a GPU hang on device.
- **Sky tcMod scroll-vs-scale resolution** (`metal_renderer_stub.c`, `LoadWorldMapData` sky branch): Q3 killsky has both `tcMod scroll` AND `tcMod scale` on stages 0 and 1 simultaneously, but our per-draw stage struct only carries one `tcMod` type. Resolution order is **scroll wins over scale** (scroll is the animation, scale is a one-time tile factor). Structured as `if (stageHasScroll) → type=1` `else if (stageHasScale) → type=4` `else → type=0`. The previous code unconditionally overrode scroll → scale whenever params[0] != 1.0 — triggering for every non-identity tile, flipping killsky's cloud layer from scrolling to a static tile. `PRINT_DEVELOPER` log in the sky stage-2 branch prints raw scale/scroll values so `\developer 1` reveals what the shader file actually declares.
- **Non-sky tcMod resolution — turb > scroll > scale** (`metal_renderer_stub.c`, `LoadWorldMapData`, runs BEFORE the sky branch when `!IsSkyShaderName`): `stage0TcModType` is zero-initialized each surface iteration and was never set for non-sky surfaces prior to this fix — `ShaderMap_GetScroll` stashed values into `s_pendingScrollS/T` but they were only consumed inside the sky branch. Lava's `tcMod scroll 0.1 0.1` never reached the draw uniform and lava rendered with static UVs. Fix: check `ShaderMap_GetTurb` → `ShaderMap_GetScroll` → `ShaderMap_GetScale` in that preference order, write the winning type into `stage0TcModType` + params. Turb wins because the molten-wobble look is the most visually distinctive of the three. Parser side adds `hasTurb` + `tcModTurbAmp/Phase/Freq` to `metalShaderMap_t`; `tcMod turb <base> <amp> <phase> <freq>` stores amp/phase/freq (base is Q3's legacy sin-table-offset, consumed but unused). `rotate`, `stretch`, `transform` variants are now explicitly consumed by the parser (even though the draw uniform can't render them yet) — otherwise their numeric params leak onto the outer parse stream and get misread as keywords, corrupting subsequent directive handling for the rest of the shader.
- **Q3 shader parser** (`metal_renderer_stub.c`): Targets the "white spheres/items" class of bugs where MD3 surfaces embed Q3 shader names whose actual texture lives in `textures/effects/` (and similar) via `scripts/*.shader` files. Key components:
  - `LoadAllShaders()` — called from `RE_BeginRegistration`. Walks every `.shader` file under `scripts/` in loaded pk3s via `ri.FS_ListFiles`/`ri.FS_ReadFile`.
  - `ParseShaderText()` — tokenizes each file with `COM_ParseExt`, tracks brace nesting, and extracts the **first stage's first** `map`/`clampmap`/`animmap` directive per shader definition. `$`-prefixed special tokens (`$lightmap`, `$whiteimage`) are skipped. Sets `tcGenEnv = qtrue` if any stage has `tcGen environment`.
  - Results stored in `s_shaderMap[MAX_SHADER_MAP_ENTRIES = 4096]` as `metalShaderMap_t` entries: `shaderName`, `mapPath`, `tcGenEnv`, plus `animMap` fields: `animFrameCount`, `animFps`, `animFrames[16]`, `animTextures[16]` (lazy-resolved handles).
  - `ShaderMap_LookupEntry(name)` — returns full `metalShaderMap_t *`; tries exact match then retries with image extension stripped via `StripImageExt()` (handles MD3s embedding shader names like `red_sphere.tga` when the shader definition uses `red_sphere`).
  - `ShaderMap_ResolveCurrentFrame(name)` — called first in `RegisterTexture`; if entry has `animFrameCount > 0`, selects frame based on `cls.realtime` and lazily registers that frame's texture. Uses **exact-name match only** (no extension-stripped fallback) plus a `s_resolving` re-entry guard to prevent infinite recursion: a frame path like `textures/sfx/flame1.tga` could strip to `textures/sfx/flame1`, match a shader whose animMap lists `flame1.tga`, and recurse back into `RegisterTexture` until the iOS watchdog SIGKILLs at map load.
  - `RegisterTexture` hook — tries `ShaderMap_ResolveCurrentFrame` first (animated path), then direct image load, then `ShaderMap_LookupEntry` static path fallback. Forward declarations `static const char *ShaderMap_Lookup(const char *name);` and `static qhandle_t ShaderMap_ResolveCurrentFrame(const char *name);` placed above `RegisterTexture`.
  - **World-surface animated shader retargeting**: `metalWorld_t` carries a parallel `int *animShaderSlots` table (one entry per draw; -1 = static, >= 0 = s_shaderMap slot) and `uint32_t animatedDrawCount`. At map load (`LoadWorldMapData`), `ShaderMap_FindAnimatedSlot(shaderName)` tags each draw that maps to an animated shader; `s_pendingAnimSlot` stashes the result across `SetupWorldDraw` for both planar and patch surfaces. In `RE_RenderScene` (gated on `s_world.animatedDrawCount > 0`), a tight loop calls `ShaderMap_AnimatedSlotCurrentHandle(slot)` per tagged draw and overwrites `draws[i].stages[0].textureHandle` with the current frame handle (updated from the old flat `draws[i].textureHandle` to match the new stage-based API) — zero-cost for maps with no animated world shaders. Effect: fire/lava/teleport-pad surfaces cycle their frames in real time instead of showing frame 0 permanently.
  - **tcMod scroll**: `metalShaderMap_t` gains `tcModScrollS`/`tcModScrollT` floats. `ParseShaderText` captures first-stage `tcMod scroll sx sy`; `ShaderMap_GetScroll(name, outS, outT)` returns values. At map load, `s_pendingScrollS/T` stash the values and are written into the stage's `tcMod=1` + `tcModParams.xy` fields via `AddWorldDrawStage`. MSL world fragment shader applies scroll as `texCoord += tcModParams.xy * timeSeconds` when `tcMod==1`. Fixes lava-flow, scrolling-fog, and similar Q3 shader effects on world geometry.
  - **skyparms / skybox**: `ParseShaderText` captures top-level `skyparms <farbox> <cloudHeight> <nearbox>` directives (outside any stage block). Non-`-` farbox basename stored in `metalShaderMap_t.skyBoxBase[MAX_QPATH]`; six lazy face handles in `skyFaceTextures[6]` (indices: `METAL_SKY_FACE_UP=0`, `METAL_SKY_FACE_DN=1`, `METAL_SKY_FACE_FT=2`, `METAL_SKY_FACE_BK=3`, `METAL_SKY_FACE_LF=4`, `METAL_SKY_FACE_RT=5`). Sky-only shaders (no `map` stage) get a placeholder `ShaderMap_Register` so the skyparms back-patch has a slot. `LoadWorldMapData` uses a 3-path sky decision tree per surface: (1) true cubemap — `skyparms` farbox is non-`-`: `GetSkyFaceTextureForSurface(shaderName, nx, ny, nz)` averages up to 4 vertex normals, picks dominant-axis face via `fabsf`, lazily calls `RegisterTexture(base + suffix)` (`_up/_dn/_ft/_bk/_lf/_rt`); (2) cloud-dome — farbox is `-` (e.g. q3dm1's `killsky`): `RegisterTexture(shaderName)` resolves to the shader's first-stage map (e.g. `killsky_1`) via the shader map, with `tcMod scroll` values already parsed, producing real scrolling clouds; (3) last-resort fallback: `EnsureSkyTexture()` 1-pixel color when neither path resolves.
  - **blendFunc parsing**: `metalShaderMap_t.blendMode` captures first-stage blendFunc: 0=opaque, 1=additive (GL_ONE/GL_ONE), 2=alpha-blend (GL_SRC_ALPHA/GL_ONE_MINUS_SRC_ALPHA or `blend`), 3=filter (GL_DST_COLOR/GL_ZERO or `filter`). `ShaderMap_GetBlendMode(name)` returns mode by delegating to `ShaderMap_LookupEntry(name)` which tries exact match then retries with file extension stripped — required because entity textures may be registered with extensions (e.g. `red_sphere.tga`) while shader definitions store the base name (`red_sphere`); a plain `stricmp` loop missed these and returned 0 (opaque). World surfaces with mode==1 get `Q3_METAL_WORLD_DRAWFLAG_ADDITIVE`; entity MD3 surfaces with mode==1 get `Q3_METAL_ENTITY_DRAWFLAG_ADDITIVE`. `metalTexture_t.blendMode` is set at `RegisterTexture` time from `ShaderMap_GetBlendMode`; the animated-frame path additionally propagates the parent shader's blendMode onto frame textures (e.g. flame4.tga) whose own names have no shader-map entry — without propagation additive animated effects render opaque.
  - **alphaFunc parsing**: `metalShaderMap_t.alphaFunc` captures first-stage `alphaFunc GT0/GE128/LT128` (0=none,1=GT0,2=GE128,3=LT128). `ShaderMap_GetAlphaFunc(name)` delegates to `ShaderMap_LookupEntry` (extension-tolerant). Propagated onto `metalTexture_t.alphaFunc` and animated frame textures at `RegisterTexture` time. Per-draw `alphaTestThreshold` set from `stage.alphaFunc` via `Coordinator.alphaTestThreshold(for:)` in the Swift world draw loop — per-draw wiring is complete.
  - **Second stage parsing**: `metalShaderMap_t` gains `stage2MapPath[MAX_QPATH]`, `stage2BlendMode`, `stage2TcModScrollS/T`, `stage2TcModScaleS/T`. `ParseShaderText` now tracks `stageIndex` (depth==2 increments on each `{`) and captures stage 2's `map`/`clampmap`, `blendFunc`, and `tcMod scroll`/`scale` separately. `ShaderMap_GetSecondStage(name, outMap, outMapSize, outBlendMode, outScaleS, outScaleT, outScrollS, outScrollT)` retrieves stage 2 info. `BlendModeFromTokens(src, dst)` helper centralizes blendFunc token → int mapping for both stages. `tcMod scale` parsing added alongside `tcMod scroll` for stage 1: `metalShaderMap_t.tcModScaleS/T` captured; `ShaderMap_GetScale(name, outS, outT)` returns values.
