# Quake3-iOS

<!-- AUTO-MANAGED: project-description -->
Native iOS port of Quake 3 Arena using Metal rendering. SwiftUI app shell wrapping an MTKView-based renderer that bridges to C/C++ engine code via a bridging header.
<!-- END AUTO-MANAGED -->

<!-- AUTO-MANAGED: architecture -->
## Architecture

```
Quake3-iOS/
├── Quake3_iOSApp.swift              # @main SwiftUI entry point
├── MetalView.swift                  # MTKView wrapper + inline MSL shaders
├── Quake3-iOS-Bridging-Header.h     # C/C++ bridge
├── Info.plist
code/                                # C/C++ Quake 3 engine source
baseq3/                              # Game assets
Resources/
```

**MetalView.swift** is the core renderer. It contains:
- `MetalView`: `UIViewRepresentable` wrapping `MTKView`
- `Coordinator`: `MTKViewDelegate` holding GPU structs and inline MSL shader source
- Three render pipelines: UI (`q3_ui_*`), World (`q3_world_*`), Entity (`q3_entity_*`)
<!-- END AUTO-MANAGED -->

<!-- AUTO-MANAGED: conventions -->
## Conventions

- Inline MSL shaders compiled at runtime from `shaderSource` string in `Coordinator`
- GPU vertex structs mirror MSL counterparts: `GPUVertex`, `GPUWorldVertex`, `GPUEntityVertex`
- Uniform structs: `Uniforms`, `WorldUniforms`, `WorldDrawUniforms`, `EntityUniforms`
- MTKView configured: `bgra8Unorm` color, `depth32Float` depth, display-rate FPS, continuous rendering (`isPaused = false`)
- Controller button bitmask: `Q3_PAD_*` constants defined in `code/ios/ios_local.h` (bits 0–15). Swift mirrors them in `GameControllerBridge.PadBit`. C side maps bits to `K_PAD0_*` keycodes in `s_gamepadBitMap[]` (ios_main.m). `IN_Frame` diffs `prev ^ cur` buttonMask and queues `SE_KEY` events per toggled bit — do not add per-button polling on top of this.
- Controller bind installation: `IN_Init` uses `Cbuf_AddText` + `Cbuf_Execute` to install all `PAD0_*` binds and joystick cvars. Do NOT use `Cbuf_ExecuteText(EXEC_NOW, ...)` for multi-line bind scripts: `EXEC_NOW` calls `Cmd_ExecuteString` on the whole string and stops at the first newline — only the first command runs, all subsequent binds are silently dropped. `Cbuf_AddText` queues the full multi-line block; `Cbuf_Execute` drains every command to completion. After the block runs, verify with `Cbuf_ExecuteText(EXEC_NOW, "bind PAD0_A\n")` etc.
<!-- END AUTO-MANAGED -->

## Patterns

- **World debug modes**: `worldDebugMode` static `Float` on `Coordinator` (default `0`). Values: `0`=normal, `1`=base texture only, `2`=lightmap only, `3`=UV1 visualization, `4`=vertex color only. Change at compile time to diagnose rendering issues.
- **Alpha-test**: NOT applied globally in the world fragment shader. Q3 `alphaFunc` is per-shader-stage opt-in. Alpha-tested stages must be driven by the Q3 shader parser, not a global `discard_fragment()` call. Unconditional discard causes transparent geometry on surfaces whose stage0 texture falls back to white.
- **Entity pipeline diagnostics**: `RE_ClearScene` resets four per-frame counters (`s_entityAcceptedThisFrame`, `s_entityRejectedNullThisFrame`, `s_entityRejectedTypeThisFrame`, `s_entityRejectedModelThisFrame`) and increments `s_clearSceneCalls`. `RE_AddRefEntityToScene` increments `s_rawEntryCount` unconditionally (even for null/invalid). `RE_RenderScene` increments `s_renderSceneCalls` and logs the per-frame accept/reject counts every `s_sceneLogCounter` interval, plus the first accepted entity's origin/axis/renderfx/hModel/reType. Use `s_clearSceneCalls`/`s_renderSceneCalls`/`s_rawEntryCount` to detect if cgame is submitting at all vs. the pipeline rejecting.
- **Tag-only MD3s**: `LoadMD3ModelData` accepts `numSurfaces == 0` (changed from `< 1` to `< 0`). Models with only tags and no renderable surfaces are valid (e.g., attachment point markers).
- **Optional model path logging**: `TryRegisterModelPath` logs missing pk3 files at `PRINT_DEVELOPER` (not `PRINT_WARNING`). Missing optional paths are expected; only log at warning level for true failures.
- **Synthetic first-person viewmodel**: `SynthesizeViewmodelEntity` (in `metal_renderer_stub.c`) appends its own viewmodel entity to `s_sceneEntities[]` each `RE_RenderScene`, independent of cgame. `GetViewmodelHandle(int weapon)` maps `weapon_t` index (0=WP_NONE … 10=WP_GRAPPLING_HOOK) to an MD3 path; models are lazily registered via `RE_RegisterModel` and cached in `s_viewmodelHandles[16]` (padded past WP_NUM_WEAPONS=11 for safety). Placement driven by five `CVAR_ARCHIVE` cvars: `metal_vm_forward` (6), `metal_vm_right` (5), `metal_vm_up` (-4), `metal_vm_scale` (0.3), `metal_vm_sway` (0.4) — live-tunable from Q3 console without rebuild. Sign convention: origin formula uses `-kRight * axis1`; axis1 is Q3 "left"; positive `metal_vm_right` subtracts left = moves right on screen. Sway: `swayRight = sin(t) * swayAmp`, `swayUp = cos(t) * (swayAmp * 0.6)`. `renderfx |= RF_DEPTHHACK`. `metalSceneEntity_t.isSynthetic` is `qtrue` for injected viewmodel, `qfalse` for cgame entities. The synthetic viewmodel always renders; cgame's own `/weapons2/` viewmodel chain is suppressed near camera (see Local-player body hiding below).
- **Entity depth-hack**: `MetalView.swift` keeps two entity depth-stencil states: `depthStencilState` (`.lessEqual`, default) and `depthHackDepthStencilState` (`.always`, depth write on). Per-draw entity loop switches state based on `draw.flags & Q3_METAL_ENTITY_DRAWFLAG_DEPTHHACK`. Used so the first-person viewmodel never gets occluded by world geometry while still self-occluding correctly.
- **World-scene state preservation** (THREE-PART, permanent architectural pattern): cgame calls `RE_ClearScene` before every scene in a frame — world scene, then each HUD/2D scene. This means ClearScene fires N times per rendered frame, not once. All three parts below must stay coherent; reverting any one causes render breakage.
  1. **`RE_ClearScene` does NOT reset `s_entityVertexCount`/`s_entityIndexCount`/`s_entityDrawCount`**. It still resets `s_sceneEntityCount` and the per-scene accept/reject counters. Rationale: resetting draw buffer counts in ClearScene wiped the world scene's built geometry before the subsequent HUD scenes' `RE_RenderScene` ran, producing nothing to draw.
  2. **In `RE_RenderScene`, the `s_entity{Vertex,Index,Draw}Count = 0` resets and the `if (s_sceneEntityCount > 0) { ... build loop ... }` block are both gated on `fd->rdflags == 0`**. Only world scenes (rdflags 0) rebuild the entity buffers; HUD scenes retain the previous world buffer intact.
  3. **In `RE_RenderScene`, the `s_sceneView` write-out (fovX/fovY/viewOrigin/viewAxis) is also gated on `fd->rdflags == 0`**. Required because preserving world entity draws is useless if sceneView is still overwritten by a HUD camera — world-space coordinates would project off-screen. Regression history: parts 2+3 alone caused all-invisible because ClearScene's buffer-count resets still ran between scenes.
- **Q3 shader parser** (`metal_renderer_stub.c`): Targets the "white spheres/items" class of bugs where MD3 surfaces embed Q3 shader names whose actual texture lives in `textures/effects/` (and similar) via `scripts/*.shader` files. Key components:
  - `LoadAllShaders()` — called from `RE_BeginRegistration`. Walks every `.shader` file under `scripts/` in loaded pk3s via `ri.FS_ListFiles`/`ri.FS_ReadFile`.
  - `ParseShaderText()` — tokenizes each file with `COM_ParseExt`, tracks brace nesting, and extracts the **first stage's first** `map`/`clampmap`/`animmap` directive per shader definition. `$`-prefixed special tokens (`$lightmap`, `$whiteimage`) are skipped. Sets `tcGenEnv = qtrue` if any stage has `tcGen environment`.
  - Results stored in `s_shaderMap[MAX_SHADER_MAP_ENTRIES = 4096]` as `metalShaderMap_t` entries: `shaderName`, `mapPath`, `tcGenEnv`, plus `animMap` fields: `animFrameCount`, `animFps`, `animFrames[16]`, `animTextures[16]` (lazy-resolved handles).
  - `ShaderMap_LookupEntry(name)` — returns full `metalShaderMap_t *`; tries exact match then retries with image extension stripped via `StripImageExt()` (handles MD3s embedding shader names like `red_sphere.tga` when the shader definition uses `red_sphere`).
  - `ShaderMap_ResolveCurrentFrame(name)` — called first in `RegisterTexture`; if entry has `animFrameCount > 0`, selects frame based on `cls.realtime` and lazily registers that frame's texture. Uses **exact-name match only** (no extension-stripped fallback) plus a `s_resolving` re-entry guard to prevent infinite recursion: a frame path like `textures/sfx/flame1.tga` could strip to `textures/sfx/flame1`, match a shader whose animMap lists `flame1.tga`, and recurse back into `RegisterTexture` until the iOS watchdog SIGKILLs at map load.
  - `RegisterTexture` hook — tries `ShaderMap_ResolveCurrentFrame` first (animated path), then direct image load, then `ShaderMap_LookupEntry` static path fallback. Forward declarations `static const char *ShaderMap_Lookup(const char *name);` and `static qhandle_t ShaderMap_ResolveCurrentFrame(const char *name);` placed above `RegisterTexture`.
  - **World-surface animated shader retargeting**: `metalWorld_t` carries a parallel `int *animShaderSlots` table (one entry per draw; -1 = static, >= 0 = s_shaderMap slot) and `uint32_t animatedDrawCount`. At map load (`LoadWorldMapData`), `ShaderMap_FindAnimatedSlot(shaderName)` tags each draw that maps to an animated shader; `s_pendingAnimSlot` stashes the result across `SetupWorldDraw` for both planar and patch surfaces. In `RE_RenderScene` (gated on `s_world.animatedDrawCount > 0`), a tight loop calls `ShaderMap_AnimatedSlotCurrentHandle(slot)` per tagged draw and overwrites `draws[i].textureHandle` with the current frame handle — zero-cost for maps with no animated world shaders. Effect: fire/lava/teleport-pad surfaces cycle their frames in real time instead of showing frame 0 permanently.
  - **tcMod scroll**: `metalShaderMap_t` gains `tcModScrollS`/`tcModScrollT` floats. `ParseShaderText` captures first-stage `tcMod scroll sx sy`; `ShaderMap_GetScroll(name, outS, outT)` returns values. At map load, `s_pendingScrollS/T` stash the values and are passed to `SetupWorldDraw` as the per-draw `texCoordScroll` uniform. MSL multiplies `texCoordScroll * timeSeconds` — no extra C-side math needed. Fixes lava-flow, scrolling-fog, and similar Q3 shader effects on world geometry.
  - **Known limitations**: `tcGen environment` envmap UV generation not done (flag captured, UVs still wrong); `blendFunc` per-stage blending not respected; `tcMod rotate/scale` not applied; only first stage captured per shader.
- **Q3 .skin file parser** (`metal_renderer_stub.c`): `RE_RegisterSkin()` now fully parses `.skin` files instead of returning a stub handle. `ParseSkinText()` splits comma-separated `surface,shader` lines, skips `tag_*` entries, stores up to `METAL_SKIN_MAX_SURFACES` mappings in `metalSkin_t`. `LookupSkinSurfaceTexture(skinHandle, surfaceName)` lazy-resolves texture handles per surface; returns sentinel `(qhandle_t)-1` when the skin mapping is empty (surface hidden). In `RE_RenderScene` entity draw loop: `customSkin` branch checked before `customShader` — hidden surfaces are skipped, skin texture overrides MD3 embedded shader, falls back to MD3 shader if skin has no mapping for that surface. Skin registry: `s_skins[METAL_SKIN_MAX]` with index-based handles `0x20000000 + idx`.
- **Overbright lightmap boost**: Q3 lightmaps are authored expecting a 2x brightness multiplier (`r_overBrightBits` default = 1 → multiply by 2^1). The world fragment shader computes `float3 lit = saturate(texel.rgb * lightmap.rgb * 2.0) * in.color.rgb`. Without the boost the world renders at half brightness. `saturate()` clamps to [0,1] so bright spots don't wrap.
- **Additive world blending**: `MetalView.swift` has a fourth pipeline `worldAdditivePipelineState` (src=one, dst=one, no depth write via `additiveDepthStencilState`). Per-draw world loop checks `draw.flags & Q3_METAL_WORLD_DRAWFLAG_ADDITIVE`; if set, switches to additive pipeline for that draw only, then restores opaque pipeline. Used for glow/effect shader stages.
- **Local-player first-person body/weapon hiding**: In `RE_RenderScene`, any non-synthetic cgame entity is proximity-tested (`distSq < 1600`, i.e. 40 world units) and skipped if its model path matches either: (a) `/players/` + ends in `/head.md3`, `/upper.md3`, or `/lower.md3` (local player body parts), or (b) contains `/weapons2/` **except** models whose name ends in `_flash.md3` (muzzle flashes). Both classes render at garbage screen positions due to the cgame.qvm ABI mismatch (renderfx bits land in wrong field). Suppressing them eliminates the ghost shotgun floating left and red polygon slashes when turning. Muzzle flashes (`*_flash.md3`) are exempted: they are transient (one frame per shot, submitted via `tag_flash`), and even mispositioned they provide 'weapon is firing' feedback — without the exemption machinegun/plasma/rail look dead on trigger pull. Distant entities (other players, bots, their weapons) still render — only the near-camera cluster is filtered. The synthetic viewmodel (`isSynthetic == qtrue`) is unaffected. All three player-body suffixes must remain in sync — hiding only head leaves torso visible when looking down.
- **IN_Init call site**: `IN_Init()` is called explicitly from `Quake3_Init()` after `Com_Init()`, not by any Q3 engine subsystem. Q3's normal platform layers (sdl_input.c, linux_glimp.c) are not linked on iOS, so the engine never invokes `IN_Init` automatically. Without the explicit call, the `Cbuf_AddText` + `Cbuf_Execute` block that installs all PAD0_* binds and joystick cvars never runs — controller buttons queue SE_KEY events that match no bindings. Do not move this call to after any config-loading code or to a deferred exec path.
