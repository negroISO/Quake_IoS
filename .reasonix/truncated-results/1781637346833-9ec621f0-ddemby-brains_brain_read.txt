# Quake3-iOS Metal Project

<!-- AUTO-MANAGED: project-description -->
Native iOS/visionOS port of Quake 3 Arena using a custom Metal rendering pipeline. SwiftUI app shell wrapping an MTKView-based renderer that bridges to the C/C++ ioq3 engine. The Metal build (`com.quake3ios.rt`) runs alongside an ioq3 reference build (`com.tomkiddcog.Quake3-iOS`) for parity comparisons. See AGENTS.md for full agent-facing instructions.

## Architecture

│   │   ├── metal_renderer_shared.h  # Shared C/Swift struct definitions (Q3MetalWorldVertex, etc.)
│   │   ├── ios_local.h              # Q3_PAD_* bitmask constants, iOS-local types

**MetalView.swift** is the monolithic renderer. It contains all GPU structs, 14 pipeline states, inline MSL source, world/entity draw loops, PBR fallback texture helpers (`pbrFlatNormalDefault`, `pbrRoughnessDefault`, `pbrMetallicDefault`, `pbrEmissiveDefault`), and the `entityAtlasIndirectNames` prefix→target table for indirect entity envmap atlas lookups. The C side (`metal_renderer_stub.c`) builds draw command structs; Swift executes them via Metal. `Q3MetalRenderer_GetPBRMaterialByName(const char *name)` in `metal_renderer_stub.c` wraps `q3_pbr_lookup_by_name` and is declared in `Quake3-iOS-Bridging-Header.h` for use by Swift indirect-name atlas lookups. **`Q3MetalOutputTargetSize(screen:) -> CGSize`** (@MainActor, top-level) derives the render target using `bounds * nativeScale` (normalized landscape) — avoids `nativeBounds` which describes the physical panel while UIKit may operate a different logical screen on iPad/OLED/external display.

**Launch-menu enums (MetalView.swift, top-level):** Persisted via `UserDefaults`; env var overrides take precedence for script-driven capture.
- **`Q3UpscaleQuality`** — MetalFX spatial upscale: `native` (no upscale), `high` (0.75×), `medium` (0.5×), `low` (480p). Key `q3_upscale_quality`, env var `Q3_UPSCALE_QUALITY`. Offscreen RT created at `renderSize(forOutput:)`, upscaled to drawable via `MTLFXSpatialScaler` each frame. `native` bypasses MetalFX entirely.
- **`Q3FrameInterpolation`** — MetalFX frame interpolation: `off` / `on`. Key `q3_frame_interpolation`, env var `Q3_FRAME_INTERPOLATION`. Off by default — no motion vectors yet; optical-flow-only interpolation ghosts on fast camera motion.
- **`Q3RTMix`** — `r_rt_mix` launcher convenience: `off`=0, `blend`=0.5, `pure`=1. Key `q3_rt_mix`, env var `Q3_RT_MIX`. Sets `r_rt_mix` cvar at boot.

**CADisplayLink frame pacer (`configureFramePacer(for:preferredFPS:)`):** Drives `MTKView.draw()` via `CADisplayLink` instead of MTKView's built-in loop. Uses `CAFrameRateRange(minimum:maximum:preferred:)` on iOS 15+ for ProMotion; falls back to `preferredFramesPerSecond`. Separate from `MTKView.preferredFramesPerSecond` (which is still set but not the primary pace driver). `displayLink` is invalidated in `deinit`.

**Render pipelines (14 total):**
- UI: `q3_ui_pipeline`
- World: opaque / filter / alpha / additive / additive-full
- Sky: opaque / additive / additive-full
- Entity: opaque / filter / alpha / additive / subtract / additive-full

**Draw loops:**
- World: 6 passes (0=opaque, 1=filter/lightmap, 2=alpha, 3=additive src-alpha, 4=additive-full ONE/ONE, 5=fog). Dispatch order is `[0, 2, 3, 4, 1, 5]` — filter/lightmap (pass 1) runs AFTER alpha and additive passes, BEFORE fog. This is intentional: multi-stage shaders that place `$lightmap` as the final stage with intermediate alpha overlays (canonical: `textures/gothic_floor/center2trn` = fire base + 2× alpha ring overlays + `$lightmap` filter) require all alpha content to be composited before the lightmap multiply. The old `0..<6` sequential order dispatched the lightmap multiply before alpha overlays, so only the fire base received lightmap darkening. **Pass-INDEX vs iteration-ordinal invariant:** `useCWorldBatchesForPass = cWorldBatchIndexBuffer != nil && worldPass <= 4` (~line 7383) is evaluated against the pass-INDEX value from `worldRenderPass`, not the loop iteration counter — correct under any reordering. Future world pass changes must preserve this distinction. **Known regression:** alpha decals without their own lightmap stage now blend onto unlit base color (pass 2 runs before pass 1 globally); correct fix is per-shader stage collapse via `MetalShaderCombinedLightmapBaseStage` (metal_renderer_stub.c:1322), not reverting order.
- **2× lightmap overbright invariant (`q3_world_fragment` MSL, ~line 2465-2480):** Two branches in `q3_world_fragment` both multiply the lightmap sample by 2.0 — **both must remain or half-brightness regresses on all lit wall/floor surfaces.** (1) Multi-pass path: `if (drawUniforms.stageUsesLightmap > 0.5) { lit *= 2.0; }` immediately after `float3 lit = texel.rgb * vc;` — fires when this draw IS the lightmap stage (filter pipeline, GL_DST_COLOR/GL_ZERO). (2) Combined fast-path: the `_pad0 > 0.5` branch samples `lightmapTexture.sample(...).rgb * 2.0` directly. Root cause: stock Q3's `R_LoadLightmaps` (tr_bsp.c) pre-multiplied lightmap texels by `r_mapOverBrightBits` during BSP load; our Metal BSP loader does NOT pre-multiply, so the ×2 must live in the fragment shader for both render paths (`r_overBrightBits 1` / `r_mapOverBrightBits 2` are set at boot). Ported from commit `c026768` on `metal-q3dm4-16_93` (NegroISO, 2026-04-27); cherry-pick was not viable due to structural world-fragment rewrite between April and June 2026 — hand-ported as equivalent. MSE improvement: avg 20.97→20.89, best 10.28→10.00 vs Vulkan reference on q3dm4. **Triage:** if floors/walls read at ~50% brightness despite correct stage routing and PBR bindings, suspect the 2× overbright path; verify on q3dm1 `killblockgeomtrn` wall or q3dm4 floor. Affected shaders: `textures/gothic_block/killblockgeomtrn`, `textures/gothic_floor/center2trn`, `largerblock3b_ow`, `skullarch_b`, and all multi-stage world shaders with a `$lightmap` filter stage.
- Entity: 6 passes (0=opaque, 1=filter, 2=alpha, 3=additive src-alpha, 4=subtract, 5=additive-full ONE/ONE)

## Build and Run Scripts

All scripts live in `scripts/` and must be run from the repo root or will `cd` there internally.

| Script | Bundle ID target | Output dir |
|--------|-----------------|------------|
| `scripts/q3dev_run.sh [slug]` | `com.quake3ios.rt` (Metal) | `~/Desktop/q3sim_sessions/<stamp>__<sha>_<slug>/` |
| `scripts/q3dev_run_ioq3.sh [slug]` | `com.tomkiddcog.Quake3-iOS` (ioq3 ref) | `~/Desktop/q3sim_sessions/<stamp>__<sha>_<slug>_ioq3/` |
| `scripts/q3push_baseq3.sh` | Metal build | Pushes `Resources/baseq3/` only |
| `scripts/q3dev_run_mac.sh [slug]` | `com.quake3ios.rt` (Catalyst) | `~/Desktop/q3sim_sessions/<stamp>__<sha>_<slug>_mac/` |
| `scripts/q3dev_run_both.sh [slug]` | both (iPad then Catalyst) | `..._dev/` + `..._mac/` session dirs |

**Env var overrides (both run scripts):**
- `DEVICE=<UUID>` — target specific device
- `DEMO=q3dm4` — demo to play (default `q3dm4`)
- `RUN_SECS=25` — runtime in seconds

**Opinionated capture defaults (`q3dev_run.sh` and `q3dev_run_mac.sh`):** Both scripts set `Q3_UPSCALE_QUALITY="${Q3_UPSCALE_QUALITY:-medium}"` (0.5× internal render resolution, ~1728×1117 source on a 3456×2234 drawable, MetalFX-upscaled to native) and `Q3_RT_MIX="${Q3_RT_MIX:-pure}"` (RT mode on). These override the app's persisted launcher `UserDefaults` — captures from these scripts reflect real 3D quality, not any accumulated 480p-or-raster drift. Override per-invocation when needed: `Q3_UPSCALE_QUALITY=native|high|low` or `Q3_RT_MIX=blend|off`.

**Visual triage hint — "crisp HUD over pixelated 3D":** If a capture shows sharp 2D HUD/scoreboard overlaid on a blurry or pixelated 3D world, the renderer was running at low upscale-source resolution (e.g. `Q3_UPSCALE_QUALITY=low` → 480p source). The MetalFX spatial scaler upscales the 3D world to drawable size; 2D draws happen AFTER the upscale at native resolution, so HUD stays crisp while world geometry looks low-res. Root cause is almost always `UserDefaults` having drifted from a prior interactive session — the run script's `:-medium` default was not in effect (script not used, or overridden). Fix: run via `q3dev_run.sh` / `q3dev_run_mac.sh` without a `Q3_UPSCALE_QUALITY` override, or set `Q3_UPSCALE_QUALITY=medium` (or `native`) explicitly.

**ioq3 build note:** `q3dev_run_ioq3.sh` assembles `autoexec.cfg` on the fly by appending a `wait 30` guard + the `LAUNCH_COMMAND` demo/video sequence to `Resources/baseq3/autoexec.cfg`. The `wait 30` is required because autoexec.cfg runs during `Com_Init`'s cvar phase, before `CL_Init` registers the `demo` command — issuing `demo q3dm4` directly yields "Unknown command demo". The ioq3 build does NOT honor `Q3_LAUNCH_COMMAND` from the environment — autoexec.cfg is the only autostart mechanism. Demo files (`.dm_68` and `.dm_73`) from `Resources/baseq3/demos/` are pushed to the device sandbox before launch.

**Disambiguation:** Metal build produces `Q3_RT.app` (`com.quake3ios.rt`); ioq3 ref build produces `Quake3-iOS.app` (`com.tomkiddcog.Quake3-iOS`). Scripts select the correct `.app` by reading `CFBundleIdentifier` from `Info.plist` inside each DerivedData candidate, then sorting by mtime.

**`[Q3-HASH-DUMP]` engine hash-dump workflow (`metal_renderer_stub.c` ~line 2102):**

## Conventions

**metal_renderer_stub.c rules (enforced by file header):**
- Do NOT add shader-name-specific fixes
- Do NOT add hardcoded visual tweaks
- Do NOT merge, skip, or reorder stages for convenience
- Cull is shader-level (not stage-level)
- Lightmap is a real stage — treat it identically to other stages
- Blend must use srcBlend/dstBlend passthrough, not compressed blendMode enum shortcuts
- Fix generic mismatches against ioq3/Kenny behavior only

**rgbGen / alphaGen mode numbering (parser-specific integers, NOT CGEN_* enum order):**
- `0` = identity, `1` = vertex, `2` = lightingDiffuse, `3` = wave, `4` = const, `5` = entity, `6` = oneMinusEntity
- Used in `ComputeRGBGen` (world fragment), entity fragment dispatch, and `WorldDrawUniforms.rgbGen`
- Mismatch is silent — shaders compile but render wrong colors

**tcGen values:** `0`=base, `1`=environment, `2`=vector (uses `tcGenVec0`/`tcGenVec1`)

**tcMod type integers:** `0`=none, `1`=scroll, `2`=wave-sin, `3`=rotate, `4`=scale, `5`=turb, `6`=stretch, `7`=transform, `8`=translate

**blendMode enum (C side, Q3MetalDrawCmd / Q3MetalWorldStage):** `0`=opaque, `1`=additive (SRC_ALPHA/ONE), `2`=alpha (src-over), `3`=filter (DST_COLOR/ZERO), `4`=subtract (ZERO/ONE_MINUS_SRC_COLOR), `5`=full-add (ONE/ONE)

**Color attachment load/store:** Always `loadAction=.load` / `storeAction=.store` — required so destination color is available for filter (GL_DST_COLOR/GL_ZERO) and subtract (GL_ZERO/GL_ONE_MINUS_SRC_COLOR) passes.

**WorldUniforms fragment binding:** Bind `WorldUniforms` to BOTH vertex index 1 AND fragment index 1 (`setFragmentBytes`). Sky fragment reads `uniforms.cameraPos`; missing fragment bind causes undefined memory reads and GPU hangs.

**MTKView drawable resolution:** `autoResizeDrawable = false`; drawable lock applied in `drawableSizeWillChange`. This pins render resolution to the engine's `r_customwidth`/`r_customheight` for valid AVI parity comparisons against ioq3.

**Cbuf ordering for multi-line bind scripts:** Use `Cbuf_AddText` + `Cbuf_Execute`, never `Cbuf_ExecuteText(EXEC_NOW, ...)` for multi-command blocks. `EXEC_NOW` stops at the first newline — subsequent binds are silently dropped.

**Controller input:** `Q3_PAD_*` bitmask constants in `code/ios/ios_local.h`. `IN_Frame` diffs `prev ^ cur` and queues `SE_KEY` events per toggled bit. Do not add per-button polling on top of this.

**`surfaceparm nodraw` handling:** `metalShaderMap_t.isNoDraw` is set by the parser when `surfaceparm nodraw` is encountered; persisted via `last->isNoDraw = gotNoDraw` at registration. The world draw path checks `_e->isNoDraw` and returns early BEFORE the stage-emit loop — utility brushes (caulk, hint, clip family, areaportal, clusterportal, donotenter, trigger, origin, skip) never reach the GPU. Do NOT route nodraw surfaces through any pipeline pass; doing so produces translucent grey cones (light-projection volumes), opaque sky-cover planes, and phantom rectangles on torch sconces.

**Magic Keyboard delete / forward-delete key routing (`Q3InputView.keyDown`):**
- `keyboardDeleteOrBackspace` (iPad Magic Keyboard's primary Delete key): emits `Q3Sys_CharEvent(8)` (ctrl-H) on key-down BEFORE sending `K_BACKSPACE` (127). Q3 edit fields (console, chat) handle backspace via `SE_CHAR` ctrl-H — `CL_CharEvent` explicitly drops 0x7f and `Field_KeyDownEvent` only handles K_DEL as forward-delete — so the SE_KEY alone was reaching Q3 as a key press but never deleting text. Sending both events preserves bind compatibility while enabling text editing.
- `keyboardDeleteForward` (Fn+Delete / external keyboard): maps to Q3 keycode 140 (K_DEL, forward delete). Previously mapped to 127 (K_BACKSPACE) — that was wrong; `Field_KeyDownEvent` handles K_DEL as forward-delete, not K_BACKSPACE.
